# Creative Spark V2.0 — 프로젝트 코드 감사 및 운영 점검 지침서 (Operation Prompt)

본 문서는 프로젝트의 보안, 견고성, 플랫폼 호환성, 코드 품질 상태를 정기적으로 감사하고 검증할 때 사용하는 **AI 어시스턴트용 운영 프롬프트(Operation Prompt)** 및 **체크리스트 지침서**입니다.

이 지침을 AI 어시스턴트에 입력하면, 본 프로젝트(Creative Spark V2.0) 및 유사한 아키텍처를 가진 프로젝트의 결함과 취약점을 자동으로 스캔하고 보고서를 작성하도록 유도할 수 있습니다.

아래 블록 전체를 복사하여 새로운 AI 코딩 어시스턴트 세션에 입력하면, 프로젝트의 취약점과 개선 사항을 체계적으로 감사받을 수 있습니다.

```markdown

- **Core Engine:** Node.js 환경에서 작동하는 마크다운 컴파일러 및 PPTX 분석/생성 JavaScript/TypeScript 스크립트군

### 2. 핵심 점검 카테고리 및 탐색 방법

#### 🔴 Category A: 치명적 취약점 & 보안 (최우선 순위)
1. **커맨드 인젝션 (Command Injection):**
   - Node.js의 `exec`, `execSync`, `spawn` 등을 사용하는 코드가 있는지 탐색하십시오.
   - 사용자 입력값(예: 스타일 ID, 파일명, 포맷 옵션 등)이 셸 명령어 문자열에 직접 삽입되는지 점검하고, 화이트리스트 검증이나 정규식 살균(Sanitization) 처리가 누락되었는지 확인하십시오.
2. **경로 탈출 (Path Traversal):**
   - 파일 읽기/쓰기(`fs.readFileSync`, `fs.writeFileSync` 등) 및 경로 조작(`path.join`, `path.resolve` 등) 부분을 검사하십시오.
   - 클라이언트에서 전달받은 디렉토리 경로에 상위 폴더 탈출 지시어(`../../`)를 삽입했을 때, 프로젝트 루트 외부 영역을 침범할 수 있는지 확인하십시오.
3. **크로스 사이트 스크립팅 (XSS):**
   - 파일 목록이나 숏코드 내용 등 검증되지 않은 외부 텍스트가 HTML 응답 포털에 템플릿 리터럴 등으로 직접 주입되는 부분이 있는지 점검하십시오.
4. **CORS & HTTP 헤더 보안:**
   - 로컬 API 응답 시 CORS 헤더(`Access-Control-Allow-Origin` 등)의 설정 여부와 안전성을 확인하십시오.
   - 파일 다운로드 기능 제공 시 `Content-Disposition` 헤더의 파일명에 헤더 분할 공격(Header Injection)을 방지하는 안전화 장치가 적용되었는지 검사하십시오.

#### 🟠 Category B: 런타임 결함 및 견고성 (높은 순위)
1. **TDZ (Temporal Dead Zone) 참조 오류:**
   - TypeScript/JavaScript 파일 내에서 `const`나 `let`으로 선언된 화살표 함수나 변수가 선언되기 이전에 호출/사용되고 있어 `ReferenceError`를 일으킬 가능성이 있는지 호이스팅 흐름을 체크하십시오.
2. **방어적 JSON 파싱 및 예외 처리:**
   - `JSON.parse`나 `localStorage.getItem` 값을 파싱하는 모든 위치를 탐색하십시오.
   - 데이터 손상이나 포맷 불일치 발생 시 전체 UI 렌더링이 중단(크래시)되는 것을 막기 위해 `try-catch` 및 폴백 구조가 구성되어 있는지 확인하십시오.
3. **플랫폼 호환성 (OS Cross-Platform Support):**
   - `powershell` 또는 Windows OS 전용 GUI 도구(예: `FolderBrowserDialog`)가 코드에 하드코딩되어 있는지 검사하십시오.
   - macOS 및 Linux 환경에서 500 에러를 내지 않고 대안 기능(예: macOS의 `osascript` 혹은 수동 입력)으로 우아하게 작동되는지 점검하십시오.

#### 🟡 Category C: 코드 중복 및 데드 코드 (유지보수 순위)
1. **WCAG 명도 대비 계산식 중복:**
   - 색상 관련 검사 로직(`getLuminance`, `getContrast`, `getWCAGRating`)이 복수의 UI 컴포넌트에 파편화되어 중복 작성되었는지 검사하십시오.
2. **핵심 파서 및 스크립트 유틸 복사:**
   - 숏코드 파서 로직(`splitMeta`, `standardizeItem`, `parseShortcodeItems` 등)이 여러 빌더 스크립트에 중복 복제되어 있는지 확인하고 공통 모듈화 여부를 체크하십시오.
3. **미사용 데드 코드 방치:**
   - 프로젝트 정적 진입점(예: `main.tsx`)에서 임포트되지 않거나, 기능적으로 대체되어 유산으로 남은 대형 컴포넌트(예: `PptxAnalyzer`와 `PptxInspectorSuite` 간 교차점 등)가 리소스를 낭비하고 있는지 점검하십시오.

#### 🟢 Category D: 설정 및 환경 관리 (운영 순위)
1. **TypeScript 엄격 모드 적용 상태:**
   - `tsconfig.json` 및 `tsconfig.app.json`을 분석하여 `strictNullChecks`, `noImplicitAny` 등의 속성이 비활성화(`false`)되어 있는지 체크하고 잠재적 런타임 Null 에러 가능성을 보고하십시오.
2. **코드 품질 도구 누락:**
   - 프로젝트 루트에 `eslint.config.js`, `.prettierrc` 등 린터/포맷터 설정 파일이 올바르게 존재하는지 점검하십시오.
3. **환경 변수 관리 외부화:**
   - 포트 번호, 출력 디렉토리 경로, 스크래치 경로 등이 상수로 고정(Hardcoded)되어 있는지 체크하고 외부 `.env` 파일 연동성을 확인하십시오.

#### 🔵 Category E: 운영 최적화 및 리소스 관리 (배포 순위)
1. **의존성 중복 및 비대화:**
   - 동일 목적의 무거운 라이브러리(예: `playwright`와 `puppeteer`)가 동시에 디펜던시에 포함되어 불필요하게 빌드 용량과 설치 리소스를 낭비하고 있는지 분석하십시오.
2. **임시 파일 생명주기 제어:**
   - API 서버 실행 혹은 초기화 시 `scratch/` 같은 임시 보관 디렉토리를 완전히 비우는 청소 로직이 누락되어 파일이 무기한 누적될 여지가 있는지 확인하십시오.
3. **무거운 라이브러리 동적 로드:**
   - `pptxgenjs`, `jszip`, `html2canvas` 등 초기 렌더링에 핵심적이지 않은 대용량 모듈들을 클라이언트 초기 번들에 포함하지 않고, 동적 임포트(Dynamic Import)를 통해 지연 로드하는지 확인하십시오.
```

## 2. 프로젝트 정기 운영 점검 체크리스트

프로젝트 운영 시 소스 코드가 안전하고 확장 가능한 상태로 유지되고 있는지 수동/자동으로 점검하는 체크리스트 기준입니다.

| 점검 영역 | 점검 대상 | 확인 사항 (Checklist) | 통과 기준 (Pass Criteria) |
|---|---|---|---|
| **보안성** | `scripts/` 내 API 핸들러 | 사용자 입력값(문자열, 파일명, 경로)이 셸 명령에 직접 조합되는가? | 모든 입력 인자는 정규식 살균 검사를 거치거나 화이트리스트 키 세트 매칭을 통과해야 함. |
| **보안성** | 파일 IO 엔드포인트 | 경로 변수에 `../`가 유입될 때 루트 디렉토리 외부의 파일에 접근할 수 있는가? | `path.resolve` 후 루트 경로를 기준으로 `startsWith` 검증을 완비해야 함. |
| **보안성** | HTTP 헤더 및 XSS | CORS 접근 제어가 설정되어 있고, 파일명 XSS 방어가 되어 있는가? | Access-Control 헤더 정의 및 파일 목록 렌더링 시 `escapeHtml` 처리가 완료되어야 함. |
| **안정성** | `src/components/` | `localStorage`에서 값을 꺼내 파싱하는 부분이 보호되고 있는가? | JSON 파싱 오류 시 기본값(Fallback)으로 대체되어 React 화면 크래시를 예방해야 함. |
| **호환성** | 로컬 시스템 호출 | 폴더 선택 API 호출 시 Windows 이외의 운영체제에서 500 에러를 유발하는가? | `process.platform`을 확인하여 `win32` 및 `darwin` 운영체제 다이얼로그로 우아하게 분기 작동되어야 함. |
| **유지보수성** | 공통 알고리즘 코드 | 동일한 가독성 판정 공식이나 파서가 여러 컴포넌트에 복사 구현되어 있는가? | `src/lib/wcag.ts` 혹은 `scripts/shortcode-utils.mjs` 등 하나의 단일 진실 공급원(Single Source of Truth)으로 수렴되어야 함. |
| **품질 제어** | 설정 파일 및 타입 | 엄격한 타입 체크 규칙이 완전히 차단되어 있는가? | `tsconfig`에서 `strictNullChecks`가 활성화되고 ESLint 표준 검사가 CI/CD 파이프라인에 포함되어야 함. |
| **자원 최적화** | `package.json` | `playwright`와 `puppeteer` 같이 리소스가 무거운 중복 라이브러리가 존재합니까? | 용도가 동일한 중복 도구는 하나로 정리하고 미사용 의존성은 빌드 구성에서 배제해야 함. |
| **자원 최적화** | `scratch/` 디렉토리 | 서버 기동 시 또는 변환이 끝난 임시 파일이 정리되지 않고 남아 있는가? | 개발 서버 구동 진입 시 scratch 폴더 초기화가 이루어지거나, 변환 완료 콜백에서 완벽히 삭제되어야 함. |

## 3. 감사 및 점검 실행 프로토콜

프로젝트 담당자는 본 지침서의 **운영 프롬프트**를 새로운 작업 세션을 시작할 때마다 AI 어시스턴트에 입력하여 다음과 같은 루틴으로 정기 검사를 수행해야 합니다.

1. **세션 초기 감사 실행:** AI 세션에 위 프롬프트를 입력하고 현재 소스 코드의 종합 점검을 요청합니다.
2. **정적 빌드 검증:** 코드를 수정하기 전후로 항상 `npx tsc --noEmit`를 실행하여 컴파일 레벨의 타입 에러가 없는지 체크합니다.
3. **취약점 스캔 검사:** 수시로 `npm audit`를 구동하여 외부 의존성 라이브러리의 DoS(ReDoS) 취약점이나 임의 파일 읽기 버그를 모니터링하고 즉시 `npm audit fix`를 시행합니다.
4. **산출물 및 임시 파일 모니터링:** API 미들웨어가 생성하는 `scratch/` 및 `publish/` 내 임시 파일들이 파일 유출 혹은 서버 재시작 시 안전하게 누적되지 않고 파기되는지 운영 모니터링을 병행합니다.
5. **번들 및 의존성 감사:** 프로덕션 배포 시 `npm run build` 산출물(`dist/`)의 전체 용량을 점검하여 비정상적으로 비대화되지 않았는지 추적 관리합니다.
